# @ryzera/pos-database

Database package for the Ryzera POS (Point of Sale) system. This package provides the Prisma ORM client and database schema management for the entire monorepo.

## 📦 Package Contents

- **Prisma Client**: Auto-generated type-safe database client
- **Database Schema**: PostgreSQL schema definitions
- **Migration Tools**: Database migration and seeding utilities

## 🚀 Quick Start

### 1. Environment Setup

Copy the example environment file and configure your database connection:

```bash
cd packages/pos-database
cp .env .env
```

Edit `.env` and update with your PostgreSQL credentials:

```env
DATABASE_URL="postgresql://your_username:your_password@localhost:5432/ryzera_db?schema=public"
```

### 2. Install Dependencies

From the monorepo root:

```bash
pnpm install
```

### 3. Generate Prisma Client

```bash
pnpm --filter @ryzera/pos-database run db:generate
```

### 4. Push Schema to Database

For development (no migrations):

```bash
pnpm --filter @ryzera/pos-database run db:push
```

Or use migrations (recommended for production):

```bash
pnpm --filter @ryzera/pos-database run db:migrate
```

### 5. Build the Package

```bash
pnpm --filter @ryzera/pos-database run build
```

This compiles TypeScript to the `dist/` folder, which is used by other packages in the monorepo.

## 📝 Database Schema

The schema includes the following models:

- **User**: System users with authentication
- **Product**: Product catalog with pricing and stock
- **InventoryLog**: Tracking inventory changes
- **SyncLog**: Synchronization logs for offline sync

See `prisma/schema.prisma` for the complete schema definition.

## 🛠️ Available Scripts

| Script | Description |
|--------|-------------|
| `pnpm run build` | Compile TypeScript to `dist/` |
| `pnpm run clean` | Remove build outputs |
| `pnpm run db:generate` | Generate Prisma Client from schema |
| `pnpm run db:migrate` | Create and apply database migrations |
| `pnpm run db:push` | Push schema changes to database (dev only) |
| `pnpm run db:reset` | Reset database and re-apply migrations |
| `pnpm run db:studio` | Open Prisma Studio (visual database browser) |


## 🔧 Development Workflow

### Making Schema Changes

1. Edit `prisma/schema.prisma`
2. Create a migration:
   ```bash
   pnpm run db:migrate
   ```
3. Regenerate the Prisma Client:
   ```bash
   pnpm run db:generate
   ```
4. Rebuild the package:
   ```bash
   pnpm run build
   ```

### Viewing Database

Use Prisma Studio for a visual interface:

```bash
pnpm run db:studio
```

This opens a browser at `http://localhost:5555` where you can view and edit data.

## ⚠️ Important Notes

### Environment Variables

- **NEVER commit `.env`** to version control
- `.env` contains sensitive database credentials
- Always use `.env.example` as a template

### Build Outputs

- The `dist/` folder is generated by the build process
- It's gitignored and should not be committed
- Other packages import from `dist/`, not source TypeScript files

### Prisma Client Location

After running `pnpm run db:generate`, the Prisma Client is generated to:
```
node_modules/.prisma/client/
node_modules/@prisma/client/
```

This is automatically handled by Prisma and referenced by the package exports.

## 🐛 Troubleshooting

### "No database URL found" Error

**Solution**: Make sure `.env` file exists with a valid `DATABASE_URL`. Copy from `.env.example` if needed.

### "Cannot find module '@ryzera/pos-database'"

**Solution**: Run `pnpm run build` to compile the TypeScript source to `dist/`.

### Type errors after schema changes

**Solution**: 
1. Run `pnpm run db:generate` to update Prisma Client
2. Run `pnpm run build` to recompile with new types

### Migration conflicts

**Solution**: If you have migration conflicts, you might need to reset:
```bash
pnpm run db:reset  # WARNING: This deletes all data!
```
